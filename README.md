# Tenshi Systems Engineering — Client Portal MVP

A branded, plain-HTML/CSS/JavaScript client portal designed to live beside the existing Tenshi Systems Engineering website on GitHub Pages. It uses the site's existing `styles.css`, `design.css`, logo and colour tokens, with portal-specific styling kept in its own stylesheet.

## Included in this package

- `client-portal.html` — secure sign-in and dashboard shell
- `client-portal.css` — responsive portal styling, scoped to `.tenshi-portal`
- `client-portal.js` — Supabase authentication and portal workflows
- `supabase/client-portal-schema.sql` — database tables, trigger, row-level security and private Storage policies
- `portal-builder-integration.patch` — one-line change for the existing portal card in `tools/build-pages.mjs`

## What works after Supabase setup

- Email/password sign-in and password reset
- Client-specific project dashboard and progress
- Project updates
- Private file upload and signed download links
- Client revision/change requests
- Project messaging
- Invoice list and optional external payment links
- Admin-only project creation and publishing project updates

The admin interface does not create Auth users or process payments. Create client accounts in Supabase Auth; Stripe checkout and invitation emails should be added through a server-side Edge Function before production use.

## Install into the existing repository

Copy these files into the root of the existing repository, keeping the SQL file in `supabase/`.

Then apply the change shown in `portal-builder-integration.patch` to `tools/build-pages.mjs`. The existing `portal.html` is generated by that script, so do not edit the generated HTML directly. After the source change, rebuild:

```bash
npm install
npm run build
```

The existing Portal card will then open `client-portal.html`.

## Supabase setup

1. Create a Supabase project.
2. Open SQL Editor and run `supabase/client-portal-schema.sql`.
3. In Project Settings → API, copy the Project URL and anon/publishable key.
4. Paste them into `client-portal.js`:
   - `SUPABASE_URL`
   - `SUPABASE_ANON_KEY`
5. In Supabase Authentication → Users, create your own administrator account.
6. The SQL trigger creates a matching `portal_profiles` row automatically.
7. Promote your account to administrator in SQL Editor:

```sql
update public.portal_profiles
set role = 'admin'
where id = (select id from auth.users where email = 'YOUR-ADMIN-EMAIL');
```

8. Create each client in Authentication → Users. The trigger creates their client profile. Add their name/company in `portal_profiles` if desired.
9. Sign in at `client-portal.html`, open Administration, create projects and publish updates.

## Important security notes

- The Supabase anon/publishable key is designed for browser use. Never put a `service_role` key in `client-portal.js`.
- Row Level Security is enabled on every portal table. The SQL policies scope client records by authenticated user ID and allow administrative actions only for profiles with `role='admin'`.
- Storage is private. Downloads use short-lived signed URLs.
- Do not enable public registration. Create/invite client accounts through the Supabase dashboard or a properly secured server-side function.
- The included client portal is an MVP foundation, not a completed payment or accounting system. Before using real customer data, test RLS with separate client/admin accounts, set Supabase Auth redirect URLs, configure email delivery, add rate limits/monitoring, and review the policies.
- GitHub Pages serves the frontend only. Supabase supplies authentication, database and storage. Do not store private client files in the public GitHub repository.
